| `CONN-SYSTEMS-MANAGER-CONNECTOR-CONTENT-R002` | **Declare the host access contract of systems-manager and add the host record tool.** Subsystem: connector `systems-manager`. Hostnames are excluded: the connector ontology (`systems_manager/ontology/systems.ttl`) deliberately keeps hostnames, addresses and hardware addresses out of the graph as a privacy policy, so the contract has no hostname column. Add ONE new read-only tool `sm_system_get_host_record` (one tool per operation) that returns one host record keyed by `host_id`, a stable opaque id (a SHA-256 hash of the machine identity, truncated to 32 hex characters), with `pendingUpdates` (count of upgradable packages) and `uptimeSeconds`; it carries no hostname. Declare in `systems_manager/ontology/access_contracts.ttl` one `ac:AccessContract` for entity `host` (class `HardwareNode`, which rolls up to the core infrastructure host class, key `host_id`, columns pendingUpdates, uptimeSeconds) setting `ac:classIri`, `ac:sourceId`, `ac:entity`, `ac:keyField`, `ac:accessKind` `mcp_tool`, `ac:operation` `sm_system_get_host_record` and `ac:pagination` `none`; column names equal the ontology property local names. Save the recorded response in `tests/recordings/host.json`; medulla copies it into its competency fixtures. The consumer is the medulla row MEDULLA-CQ-CONN-R001.2. Caller chain: arbora `fleet.call` reaches `sm_system_get_host_record` in `systems_manager/mcp_server.py`, which routes to `get_host_record` in `systems_manager/systems_manager.py`; its result is validated against the `ac:AccessContract` declared in `systems_manager/ontology/access_contracts.ttl`. Shape: one new tool, one new manager method, one contract file, one recording; the tool is classified a sensitive read by the existing policy. | Test: `tests/test_access_contracts.py::test_competency_contracts_certified` (L2) parses the contract, calls the served tool through the MCP client against the recorded host, and asserts the key and bound fields exist and no hostname is present. |

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-SYSTEMS-MANAGER-CONNECTOR-IDENTITY-R001` | **Fleet name.** `pyproject.toml` declares `systems-manager-mcp` as the single `scion_sdk.connector` entry point. The content pack, the manifest `connector`, the fingerprints and the ingest binding all carry `systems-manager-mcp`. Caller chain: `systems-manager` in `pyproject.toml` runs `systems_manager.systems_manager:main`, which builds the server from the `scion_sdk.connector` entry point `systems_manager:connector` (`systems_manager/__init__.py:11`); `connector_name("systems_manager")` in the SDK resolves the same entry point name for the content pack, the manifest and the ingest binding. Shape: `pyproject.toml` entry point `systems-manager-mcp`, the `connector_name` helper of the SDK and the `ConnectorContent`/`IngestBinding` calls under `systems_manager/`; reuses the SDK name resolution and adds no second constant. Proving test: `tests/test_fleet_name.py::test_connector_name_is_the_fleet_name`. | Every connector name in the package is `systems-manager-mcp`. |
| `CONN-SYSTEMS-MANAGER-CONNECTOR-IDENTITY-R002` | **Windows portability.** The package imports and runs on Windows with no POSIX-only module or API (`pwd`, `grp`, `fcntl`, `termios`, `resource`, `getloadavg`, `killpg`, `sudo`, `bash`, a hard-coded `/` volume root). Windows hosts use their own implementations (winget, PowerShell, `schtasks`, `shutdown.exe`); where an operation has no Windows meaning (nvm bash bootstrap, the POSIX elevation helper, Kubernetes node detection) it returns a typed `Unsupported on this platform` result and never raises. Caller chain: the package imports on every platform; each OS branch of `systems_manager/os_provider.py` and the managers selects by `platform.system`. Shape: Windows branches in `systems_manager/` with no POSIX-only module; the Windows CI job runs the whole suite. Proving test: `tests/test_windows_portability.py::test_package_imports_no_posix_only_modules`. | Every Windows branch passes under monkeypatched `platform.system` / `os.name`, and the Windows CI job runs the full suite. |
| `CONN-SYSTEMS-MANAGER-CONNECTOR-IDENTITY-R003` | **Mutations refuse cleanly and accept `confirm=true`.** Every mutating tool (`sm_system_operations`, `sm_service_operations`, `sm_process_operations`, `sm_file_operations` `manage_file`, `sm_cron_operations`, `sm_firewall_operations`, `sm_advanced_operations`, `manage_service`, `start_system_trace`, `stop_system_trace`) takes `confirm`, in addition to administrator policy, and decides through the SDK `ctx_confirm_destructive`. A client that did not advertise elicitation and did not pass `confirm=true` gets a non-error `cancelled` result whose `reason` names `confirm=true` and nothing changes; `confirm=true` performs it; an eliciting client is asked. A missing context fails closed. Caller chain: a client calls a mutating `sm_*` tool of `systems_manager/mcp_server.py` on stdio or HTTP; the SDK refuses a client that cannot elicit and did not send `confirm=true`. Shape: the confirmation handling of the mutating tools in `systems_manager/mcp_server.py`; reuses the SDK refusal. Proving test: `tests/test_destructive_confirmation_transports.py::test_stdio_no_auth_mutation`. | A non-eliciting client is refused with `confirm=true` named, then succeeds with `confirm=true`, on every transport. |
